# E-19 — Listar MenuItem administrativos

## Endpoint versionado

`GET /v1/restaurants/{restaurantId}/menu-items`

Proveedor: Menu. Dirección: entrada.

## Autorización y headers

Bearer válido, permiso `menu:definition:read` y ámbito restaurante. 401 sin identidad válida; 403 sin permiso/ámbito. Accept: application/json; JSON UTF-8. Es una lectura: no requiere Idempotency-Key ni If-Match.

## Parámetros

restaurantId identifica el ámbito autorizado. Query: cursor opaco opcional; limit entero entre 1 y 200, por defecto 50; reviewState opcional UP_TO_DATE o REVIEW_REQUIRED filtra solo combos. Sin filtro incluye STOCKED/PREPARED con reviewState null. Conservar filtros al continuar el cursor. Valores inválidos producen 400.

## Body

No aplica. GET sin body.

## Respuesta

200. [Schema](../../schemas/AdminMenuItemPage.schema.json). Content-Type: application/json; Cache-Control: no-store; ETag opaco de la representación administrativa.

```json
{
  "items": [
    {
      "menuItemId": "mi-combo",
      "name": "Combo",
      "fulfillmentType": "COMBO",
      "reviewState": "REVIEW_REQUIRED",
      "pendingVariantIds": [
        "v-combo"
      ]
    }
  ],
  "nextCursor": null
}
```

## Comportamiento y errores

Aplicar la [semántica de revisión](../../05-revision-combos.md). Una búsqueda válida sin coincidencias devuelve items vacío y nextCursor null. 400 formato o filtro inválido; 409 CURSOR_EXPIRED; 500/503 según convenciones. Respetar 401/403 y no exponer artículos de otro restaurante. Errores usan Error con violations. Esta lectura no confirma cambios.
