# M-01 — Definición plana cambiada

**Dirección respecto a Menu:** salida. **Canal y type versionado:** `menu.availability-definition.changed.v1`.

**Emisor:** Menu. **Receptor:** Inventory. No es endpoint HTTP.

## Autorización

ACL del broker permite publicar solo a la identidad del emisor y consumir solo al receptor autorizado para restaurantId. Menu contrasta producer con identidad autenticada. Consumidores configurados se registran por identidad de servicio, no por un replyTo enviado en datos. 

## Payload completo

Esquema: [EventM01](../../schemas/EventM01.schema.json). Envelope y data son obligatorios; correlationId es opcional y causationId no forma parte de esta revisión. Ejemplo JSON válido:

```json
{
  "messageId": "msg-m-01",
  "type": "menu.availability-definition.changed.v1",
  "schemaVersion": 1,
  "occurredAt": "2026-09-11T16:00:00-06:00",
  "producer": "Menu",
  "restaurantId": "r-1",
  "data": {
    "availabilityKey": "ak-1",
    "definitionRevision": 1,
    "items": [
      {
        "inventoryItemId": "i-agua",
        "quantity": "1",
        "unit": "unit"
      }
    ]
  }
}
```

## Procesamiento y resultado

Emitir por cambio de insumos/referencia/cantidad de una variante u opción suministrada. Reemplazo completo, no delta de stock. definitionRevision crece por clave, misma revisión y mismo contenido es duplicado, contenido distinto es conflicto. Inventory no interpreta MenuItem/variantes/recetas. Resultado esperado: M-03 para esa clave/revisión. Emitir desde outbox junto al cambio de Menu. No emitir como eco de una evaluación.

ACK del broker significa entrada persistida/procesada según convenciones, no aceptación de una venta. Error estructural o versión incompatible produce cuarentena durable; fallo transitorio conserva trabajo para reintento. No se define código HTTP para un mensaje.
