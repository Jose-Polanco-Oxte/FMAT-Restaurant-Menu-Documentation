# M-02 — Definición plana retirada

**Dirección respecto a Menu:** salida. **Canal y type versionado:** `menu.availability-definition.withdrawn.v1`.

**Emisor:** Menu. **Receptor:** Inventory. No es endpoint HTTP.

## Autorización

ACL del broker permite publicar solo a la identidad del emisor y consumir solo al receptor autorizado para restaurantId. Menu contrasta producer con identidad autenticada. Consumidores configurados se registran por identidad de servicio, no por un replyTo enviado en datos. 

## Payload completo

Esquema: [EventM02](../../schemas/EventM02.schema.json). Envelope y data son obligatorios; correlationId es opcional y causationId no forma parte de esta revisión. Ejemplo JSON válido:

```json
{
  "messageId": "msg-m-02",
  "type": "menu.availability-definition.withdrawn.v1",
  "schemaVersion": 1,
  "occurredAt": "2026-09-11T16:00:00-06:00",
  "producer": "Menu",
  "restaurantId": "r-1",
  "data": {
    "availabilityKey": "ak-1",
    "definitionRevision": 2
  }
}
```

## Procesamiento y resultado

Menu incrementa revisión y conserva tombstone. Desde la retirada no hay elegibilidad por esa clave. Consumidor no resucita definición por M-01 retrasado. Reintroducir requiere revisión mayor. Sin respuesta de negocio obligatoria; E-18 permite conciliar estado y tombstones.

ACK del broker significa entrada persistida/procesada según convenciones, no aceptación de una venta. Error estructural o versión incompatible produce cuarentena durable; fallo transitorio conserva trabajo para reintento. No se define código HTTP para un mensaje.
