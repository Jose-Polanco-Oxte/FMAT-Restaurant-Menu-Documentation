# M-04 — Pedir reevaluación

**Dirección respecto a Menu:** salida. **Canal y type versionado:** `menu.availability.reevaluation-requested.v1`.

**Emisor:** Menu. **Receptor:** Inventory. No es endpoint HTTP.

## Autorización

ACL del broker permite publicar solo a la identidad del emisor y consumir solo al receptor autorizado para restaurantId. Menu contrasta producer con identidad autenticada. Consumidores configurados se registran por identidad de servicio, no por un replyTo enviado en datos. 

## Payload completo

Esquema: [EventM04](../../schemas/EventM04.schema.json). Envelope y data son obligatorios; correlationId es opcional y causationId no forma parte de esta revisión. Ejemplo JSON válido:

```json
{
  "messageId": "msg-m-04",
  "type": "menu.availability.reevaluation-requested.v1",
  "schemaVersion": 1,
  "occurredAt": "2026-09-11T16:00:00-06:00",
  "producer": "Menu",
  "restaurantId": "r-1",
  "data": {
    "keys": [
      {
        "availabilityKey": "ak-1",
        "definitionRevision": 1
      }
    ],
    "reevaluationRequestId": "reeval-1"
  }
}
```

## Procesamiento y resultado

Comando de recuperación o renovación, no movimiento. Menu genera reevaluationRequestId al iniciar esta petición; Inventory copia ese valor en cada M-03 que responde a ella. correlationId, si se incluye, solo sirve para seguimiento y no determina recuperación. Menu registra solicitud pendiente y exige respuesta nueva con el mismo reevaluationRequestId para salir de recuperación, sin aceptar un positivo viejo retrasado. Clave desconocida se concilia con E-18, nunca se inventa lista vacía. Lista keys no vacía, sin duplicados. Duplicar entrega no necesita nueva identidad de intención. Fallo silencioso mantiene no disponible, reenvío de petición pendiente.

ACK del broker significa entrada persistida/procesada según convenciones, no aceptación de una venta. Error estructural o versión incompatible produce cuarentena durable; fallo transitorio conserva trabajo para reintento. No se define código HTTP para un mensaje.
