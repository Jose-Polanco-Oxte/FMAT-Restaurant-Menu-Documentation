# M-07 — Definición comercial cambiada

**Dirección respecto a Menu:** salida. **Canal y type versionado:** `menu.menu-item.changed.v1`.

**Emisor:** Menu. **Receptor:** Consumidores de catálogo autorizados. No es endpoint HTTP.

## Autorización

ACL del broker permite publicar solo a la identidad del emisor y consumir solo al receptor autorizado para restaurantId. Menu contrasta producer con identidad autenticada. Consumidores configurados se registran por identidad de servicio, no por un replyTo enviado en datos. 

## Payload completo

Esquema: [EventM07](../../schemas/EventM07.schema.json). Envelope y data son obligatorios; correlationId es opcional y causationId no forma parte de esta revisión. Ejemplo JSON válido:

```json
{
  "messageId": "msg-m-07",
  "type": "menu.menu-item.changed.v1",
  "schemaVersion": 1,
  "occurredAt": "2026-09-11T16:00:00-06:00",
  "producer": "Menu",
  "restaurantId": "r-1",
  "data": {
    "menuItemId": "mi-agua",
    "menuItemVersion": "1_2026-09-11T15:47:26-06:00"
  }
}
```

## Procesamiento y resultado

Invalidación por cambio efectivo de definición, incluyendo estado/archivo. Lectura E-03 o E-14 recupera contenido según propósito. No modifica datos históricos del consumidor. Comparar contador por identidad; no comparar cadena lexicalmente. No emitir cambio comercial por simple evaluación de stock. Recipe editada no cambia MenuItem hasta adopción explícita. No requiere respuesta de negocio.

ACK del broker significa entrada persistida/procesada según convenciones, no aceptación de una venta. Error estructural o versión incompatible produce cuarentena durable; fallo transitorio conserva trabajo para reintento. No se define código HTTP para un mensaje.
