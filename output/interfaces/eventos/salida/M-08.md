# M-08 — Disponibilidad comercial cambiada

**Dirección respecto a Menu:** salida. **Canal y type versionado:** `menu.menu-item.availability-changed.v1`.

**Emisor:** Menu. **Receptor:** Consumidores de catálogo autorizados. No es endpoint HTTP.

## Autorización

ACL del broker permite publicar solo a la identidad del emisor y consumir solo al receptor autorizado para restaurantId. Menu contrasta producer con identidad autenticada. Consumidores configurados se registran por identidad de servicio, no por un replyTo enviado en datos. 

## Payload completo

Esquema: [EventM08](../../schemas/EventM08.schema.json). Envelope y data son obligatorios; correlationId es opcional y causationId no forma parte de esta revisión. Ejemplo JSON válido:

```json
{
  "messageId": "msg-m-08",
  "type": "menu.menu-item.availability-changed.v1",
  "schemaVersion": 1,
  "occurredAt": "2026-09-11T16:00:00-06:00",
  "producer": "Menu",
  "restaurantId": "r-1",
  "data": {
    "menuItemId": "mi-agua",
    "menuItemVersion": "1_2026-09-11T15:47:26-06:00",
    "availabilityRevision": 3
  }
}
```

## Procesamiento y resultado

Invalidación de vista por evaluación, expiración o caída detectada. Consumidor consulta E-03; evento no asegura stock positivo. availabilityRevision creciente por MenuItem, independiente de versión comercial. Mantener máximo por versión y recargar ante nueva versión. Menu no remite este evento a Inventory. No exige respuesta de negocio.

ACK del broker significa entrada persistida/procesada según convenciones, no aceptación de una venta. Error estructural o versión incompatible produce cuarentena durable; fallo transitorio conserva trabajo para reintento. No se define código HTTP para un mensaje.
